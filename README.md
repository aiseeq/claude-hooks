# claude-hooks

Хуки для Claude Code CLI: уведомляют о завершении работы и о вопросах, показывают состояние сессии в строке статуса и в заголовке окна, не пускают в Jira комментарии в агентском стиле.

## Что делает

### Инструменты

| Инструмент | Событие | Что делает |
|---|---|---|
| `notifier` | Stop, Notification | звук и desktop-уведомление: когда Claude закончил работу и когда спрашивает разрешение или ждёт ответа. Остановка с работающими фоновыми задачами (субагенты, фоновые команды, Monitor) или взведённым будильником (`/loop`, `ScheduleWakeup`, `CronCreate`) уведомления не даёт — оно придёт после завершения последней. Клик по уведомлению переводит фокус на окно терминала |
| `jira_style` | PreToolUse (Bash) | блокирует `curl` с комментарием в Jira (`/rest/api/[23]/issue/*/comment`), если в тексте длинное тире, markdown, типографские кавычки, оборот «X, а не Y» (и узкие формы «это не X, а Y», «не из X, а из Y»), приветствие в начале или число прописью перед словом: такой текст написан мимо скилла write-as-user. Тело ищется и в раскодированных строках JSON (`\uXXXX` от `json.dumps`) |

### Строка статуса

Команда `statusline` рисует две строки под приглашением ввода и обновляет заголовок окна — подробности в разделе [«Строка статуса и заголовок окна»](#строка-статуса-и-заголовок-окна).


## Установка

Сборка идёт через [graft](https://github.com/aiseeq/graft) (задачи в `.graft.yaml`):

```bash
go install github.com/aiseeq/graft@v0.4.0
git clone https://github.com/aiseeq/claude-hooks.git
cd claude-hooks
graft install
```

Устанавливает бинарь в `~/.claude/hooks/claude-hooks` и конфигурацию в `~/.claude/hooks/config.yaml`.
Существующая конфигурация не перезаписывается: новая версия кладётся рядом как `config.yaml.new`.

Затем добавь блок `hooks` из [`configs/settings-snippet.json`](configs/settings-snippet.json) в `~/.claude/settings.json`:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "$HOME/.claude/hooks/claude-hooks pre-tool-use", "timeout": 3 }]
      }
    ],
    "UserPromptSubmit": [
      {
        "hooks": [{ "type": "command", "command": "$HOME/.claude/hooks/claude-hooks user-prompt-submit", "timeout": 3 }]
      }
    ],
    "Notification": [
      {
        "hooks": [{ "type": "command", "command": "$HOME/.claude/hooks/claude-hooks notification", "timeout": 3 }]
      }
    ],
    "Stop": [
      {
        "hooks": [{ "type": "command", "command": "$HOME/.claude/hooks/claude-hooks stop", "timeout": 3 }]
      }
    ]
  },
  "statusLine": {
    "type": "command",
    "command": "$HOME/.claude/hooks/claude-hooks statusline",
    "padding": 0
  }
}
```

`timeout` в настройках Claude Code задаётся **в секундах**.

## Конфигурация

`~/.claude/hooks/config.yaml` — см. комментарии в [`configs/hooks.yaml`](configs/hooks.yaml).

Неизвестные ключи в конфигурации считаются ошибкой — опечатка в имени поля не отключит проверку молча. Поэтому после обновления с версии, где были `validators`, `bash` и `formatter`, эти разделы нужно убрать из `~/.claude/hooks/config.yaml`.

Проверить и посмотреть текущую конфигурацию:

```bash
claude-hooks config validate
claude-hooks config show
```

### Имя проекта в уведомлении

Берётся из рабочего каталога сессии, без привязки к какому-либо одному месту для проектов:

| Каталог | Имя в уведомлении |
|---|---|
| `~/work/claude-hooks` | `claude-hooks` |
| `~/git/life` | `life` |
| `~` | `~` |
| `~/work/projecta/backend` | `projecta/backend` |

Вложенные проекты показываются вместе с родительским каталогом: иначе `~/work/projecta/backend` и `~/work/glint/backend` выглядели бы одинаково.

Если Claude Code не передал рабочий каталог, имя восстанавливается из пути транскрипта (`~/.claude/projects/-home-user-work-claude-hooks/`). Кодирование там неоднозначно — дефис бывает и разделителем каталогов, и частью имени, — поэтому вариант разбора проверяется по файловой системе.

## Строка статуса и заголовок окна

Claude Code передаёт команде `statusline` данные сессии в JSON и печатает её вывод под приглашением ввода:

```
 CLAUDE-HOOKS  · main ●3 · Opus 5·high · ctx ▓▓▓▓░░░░░░ 47% · +412 −87
```

Имя проекта выводится плашкой в инверсных цветах: строка статуса должна читаться боковым зрением. Полного пути в строке нет — плашка уже называет проект. Цвет плашки показывает, чего сессия ждёт:

| Цвет | Состояние |
|---|---|
| синий | Claude работает |
| янтарный | Claude спрашивает разрешение или ждёт ответа |
| красный | контекст заполнен больше чем на 85% — скоро сожмётся история |

Цвета берутся из палитры в 256 значений, а не из восьмицветной: базовые цвета терминала переопределяются темой, и жёлтый фон выходит грязно-коричневым.

Остальное собирается из того, что прислал Claude Code, и пустых разделителей не оставляет:

| Элемент | Значение |
|---|---|
| `main ●3 ↑2 ↓1` | ветка, изменённые файлы, коммиты впереди и позади remote |
| `main …` | git не успел посчитать изменения за 300 мс |
| `Opus 5·high` | модель и уровень рассуждений; уточнение в скобках («Opus 5 (1M context)») отбрасывается |
| `ctx ▓▓▓▓░░░░░░ 47%` | заполнение контекстного окна |
| `+412 −87` | добавленные и удалённые строки за сессию |

Неотслеживаемые файлы в счётчик изменений не входят: их обход в больших деревьях заметно дороже, а строка рисуется на каждое сообщение. Опрос репозитория ограничен 300 мс — подвисший `git` вывод не задержит. Изменения и расхождение с remote считаются одним вызовом `git --no-optional-locks status --porcelain=v2 --branch`: строка статуса не пишет индекс и не отнимает `index.lock` у git-команд человека и Claude.

После checkout или сборки, переписавшей тысячи файлов, `git status` в большом репозитории занимает секунды, и строка показывает `main …`, пока индекс не обновит первая же обычная git-команда. Сама строка статуса индекс не обновляет: фоновое обновление держало бы `index.lock` и роняло git-команды агентов в том же репозитории.

Состояние сессии строка статуса определить не может: она запускается отдельным процессом и о происходящем не знает. Его записывают хуки в `$XDG_RUNTIME_DIR/claude-hooks/sessions/`: `UserPromptSubmit` — «работает», `Notification` — «ждёт ответа», `Stop` — «готово» или «на паузе», если Claude ждёт фоновые задачи (строка статуса показывает паузу как работу). Каталог времени выполнения очищается при перезагрузке, записи старше суток удаляются попутно.

Состояние нужно не только строке статуса. Пока Claude ждёт, Claude Code напоминает о себе тем же событием `Notification` — раз в минуту, пока ответа нет. Уведомление отправляется только на переход из работы: человека уже позвали один раз, по вкладкам он пройдётся сам. Поэтому и нужен хук `UserPromptSubmit` — без него ответ, не потребовавший ни одного вызова инструмента, не считался бы возобновлением работы, и о его завершении не сообщили бы.

Вызовы инструментов состояние не меняют, хотя и означают работу: их делают и субагенты, в том числе фоновые. Такой вызов посреди ожидания выглядел бы возобновлением работы, и следующее напоминание снова зазвонило бы. Границы хода задают только запрос человека и остановка. Заодно из горячего пути ушла запись файла на каждый вызов инструмента.

Остановка при живых фоновых задачах или взведённом будильнике концом работы не считается: Claude вернётся к ней сам. Оба списка Claude Code передаёт в stdin хука `Stop` (`background_tasks`, `session_crons`, с версии 2.1.145), транскрипт хук не читает. Такой `Stop` переводит сессию в «паузу» без уведомления; следующий `Stop` с пустыми списками — это «готово» со звонком. Минутное напоминание об ожидании ввода (`idle_prompt`) во время паузы глушится; запрос разрешения проходит всегда — без ответа человека сессия встанет. Уведомления, которые ответа не ждут (`auth_success`, `elicitation_complete`, `elicitation_response`, `agent_completed`), не звонят; неизвестный новый тип считается вопросом.

Намеренно вечная фоновая задача (dev-сервер, watcher) глушила бы уведомления до конца сессии, поэтому задача, которую `Stop` видит дольше двух часов, больше не держит паузу. Время первого появления задачи хранится рядом с состоянием сессии; честно-долгая задача в худшем случае даёт один лишний звонок. Если Claude Code не передал списки вовсе, хук считает, что ждать нечего: лишний звонок лучше пропущенного.

Завершение субагента приходит отдельным событием `SubagentStop`, и хука на него нет: уведомлять о каждом из них незачем.

### Заголовок окна

Одновременно со строкой статуса обновляется заголовок окна — по нему сессия видна в панели задач и в переключателе окон, даже когда окно неактивно:

```
🟡 claude-hooks
```

Только значок состояния и проект, ветка видна в строке статуса: 🔵 — работает, 🟡 — ждёт ответа, ✅ — готово, 🔴 — контекст на исходе. Тот же заголовок ставят уведомления.

Konsole собирает заголовок по шаблону (`%d : %n` по умолчанию) и escape-последовательность OSC при этом игнорирует, поэтому шаблон заменяется целиком через `org.kde.konsole.Session.setTabTitleFormat`. Шаблон применяется не сразу — Konsole пересобирает заголовок по событиям сессии, — поэтому текущий заголовок задаётся ещё и напрямую через `setTitle`. Сессия находится по переменным `KONSOLE_DBUS_SERVICE` и `KONSOLE_DBUS_SESSION`, которые Konsole передаёт своим процессам. В остальных терминалах заголовок ставится обычной последовательностью OSC 0.

### Заголовок крупными буквами в Konsole

Заголовок виден в панели вкладок, но при одной вкладке она по умолчанию скрыта. Чтобы показывать её всегда и увеличить шрифт, нужен файл `~/.config/konsole/tabbar.css`:

```css
QTabBar::tab {
    font-size: 16pt;
    font-weight: normal;
    padding: 2px 12px;
    min-height: 24px;
}
```

Жирное начертание на таком кегле сливается — размера достаточно и без него.

и настройки Konsole:

```bash
kwriteconfig6 --file konsolerc --group TabBar --key TabBarVisibility AlwaysShowTabBar
kwriteconfig6 --file konsolerc --group TabBar --key ExpandTabWidth true
kwriteconfig6 --file konsolerc --group TabBar --key TabBarUseUserStyleSheet true
kwriteconfig6 --file konsolerc --group TabBar --key TabBarUserStyleSheetFile "file://$HOME/.config/konsole/tabbar.css"
```

Настройки читаются при запуске Konsole — уже открытые окна их не подхватят.

## Переход к окну по клику

Когда Claude ждёт ответа, клик по уведомлению переключает фокус на то окно терминала, из которого пришёл вопрос — даже если окон Konsole открыто восемь.

Как это устроено:

1. Хук поднимается по цепочке `/proc/<pid>/stat` от себя до корня и собирает PID всех процессов-предков. Окно принадлежит одному из них, и знать конкретный эмулятор терминала не требуется.
2. Уведомление отправляется напрямую через `org.freedesktop.Notifications` с действием `default` — в KDE оно срабатывает при клике по телу уведомления, а не только по кнопке.
3. Ожидание клика вынесено в отдельный процесс (`setsid`): хук завершается за считанные миллисекунды, Claude Code его не ждёт.
4. По клику в KWin загружается временный JS-скрипт, который находит окно с подходящим PID и присваивает `workspace.activeWindow`.

Четвёртый шаг — единственный способ передать фокус в Wayland: X11-API удалены, а протокол `xdg-activation` требует токена, выданного в ответ на действие пользователя. Изнутри компоновщика это ограничение не действует, поэтому код выполняется в самом KWin. На X11 работает тот же путь.

Требуется KDE Plasma (KWin 6). В других окружениях уведомление показывается, но без действия по клику — сбоя не происходит. Отключается опцией `activate_on_click: false`.

### Уведомления из других инструментов

Тем же механизмом может пользоваться любой агент или скрипт — командой `notify`:

```bash
claude-hooks notify \
  --title "opencode ждёт ответа" \
  --message "Проект: projecta" \
  --app-name opencode \
  --window-pid $$
```

`--window-pid` задаёт процесс, от которого ищется окно; без него берётся сам вызывающий. Указывать его нужно, если команда запускается отсоединённой (`setsid`, `spawn` с `detached`) — такой процесс своих предков уже не помнит.

Команда возвращает управление сразу: звук и ожидание клика уходят в фоновый процесс.

Пример для плагина [opencode](https://opencode.ai) — событие `session.idle` и запрос разрешения:

```js
import { spawn } from "node:child_process"

const notifier = `${process.env.HOME}/.claude/hooks/claude-hooks`

function notify(title, message) {
  const child = spawn(notifier, [
    "notify",
    "--title", title,
    "--message", message,
    "--app-name", "opencode",
    "--window-pid", String(process.pid),
  ], { detached: true, stdio: "ignore" })
  child.on("error", () => {})
  child.unref()
}
```

## Как это работает

Claude Code передаёт хуку JSON на stdin и интерпретирует код возврата:

| Код | Значение |
|---|---|
| 0 | операция разрешена |
| 2 | операция заблокирована, stderr передаётся модели |
| 1 | ошибка самого хука — операция не блокируется |

Логи пишутся в `~/.claude/logs/claude-hooks.log` и ротируются при превышении `max_size_mb`.

## Разработка

```bash
graft init       # один раз после клона: git-хуки, проверка glint
graft build      # сборка в bin/
graft test       # тесты; graft test -- -run TestX
graft test-race  # тесты с детектором гонок
graft cover      # покрытие
graft lint       # go vet + golangci-lint
graft glint      # glint
graft fmt        # форматирование
graft help       # все задачи
graft commit -m "fix: ..."  # гейт (сборка и тесты), коммит, push
```

## Требования

- Linux, Go 1.21+, Claude Code 2.1.145+ (поля `background_tasks`/`session_crons` в Stop)
- `canberra-gtk-play` или `paplay` — опционально, для звука уведомлений
- KDE Plasma (KWin 6) — для перехода к окну по клику
- Konsole — для заголовка окна; в других терминалах используется OSC 0
